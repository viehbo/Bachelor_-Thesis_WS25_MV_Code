\chapter{Visualization}

The objective of this project is not just the development of an interactive visualization tool, but the support of a structured data preselection process for potential machine learning applications.
The visualization component serves as an analytical instrument to explore correlations, assess data quality, and identify relevant feature candidates before model training.

Within the context of Artificial Intelligence and Computer Graphics, the work combines efficient data handling with interactive visual exploration. Large-scale climate datasets such as ERA5 are high-dimensional and spatio-temporal.
The Direct application of machine learning methods without prior inspection may lead to inappropriate feature selection or unnecessary computational cost. Interactive visualization enables hypothesis checking, feature screening, and validation before committing to automated modeling approaches.

The \textit{glaciVis} therefore acts as a bridge between raw geospatial climate data and structured machine learning workflows.


\section{Conceptual Design Choices}
\label{sec:conceptual_design_choices}

The central design goal is to provide a structured environment for data exploration that supports feature understanding. ERA5 and WGMS datasets contain spatial and temporal dimensions that must be analyzed jointly. According to Aigner et al. \parencite[p.380]{aigner_time_oriented_data}, time-oriented data benefit from coordinated views that combine spatial context with temporal detail. 

The interface is therefore separated into four functional sections:

\begin{itemize}
    \item Data definition (file selection)
    \item Parameter configuration (selection and filtering)
    \item Spatial inspection
    \item Temporal inspection
\end{itemize}

The workflow follows a top-down and left-to-right logic. Interaction starts with data definition and ends with temporal analysis. This controlled interaction flow reduces cognitive complexity and prevents inconsistent view states, as emphasized in time-oriented visualization research \parencite{aigner_time_oriented_data}.

\[
\textbf{File selection} \rightarrow 
\textbf{Adjustments and controls} \rightarrow 
\textbf{Map} \rightarrow 
\textbf{Line plot}
\]

The restriction of influence to a single direction ensures transparency, reproducibility, and a clear analytical sequence.
Users first define the data scope, then configure variables, inspect spatial structure, and finally analyze temporal behavior.

\section{Data Preprocessing}

ERA5 data are provided in GRIB format \parencite{ecmwf_grib_explanation}. While GRIB is efficient for distribution and storage, it is not optimal for interactive exploration. The format requires decoding before structured slicing of spatio-temporal subsets is possible.

According to \textcite[pp.~85--87]{python_maps}, the Python library \textit{Xarray} is optimized for labeled multi-dimensional computations and geospatial data handling. Both \textit{Python Maps} \parencite[p.~88]{python_maps} and the official Xarray documentation \parencite{xarray_documentation} recommend NetCDF as an efficient storage format. NetCDF provides a self-describing and platform-independent structure that supports indexed access and slicing \parencite{netcdf_documentation}.

From a machine learning perspective, preprocessing serves two primary purposes:

\begin{itemize}
    \item Improving computational efficiency
    \item Ensuring feature consistency
\end{itemize}

Converting GRIB to NetCDF enables structured slicing of spatial and temporal subsets, which is essential when extracting training samples or performing correlation analysis.

Wind data are originally stored as horizontal vector components $u$ and $v$. For exploratory feature screening, the wind magnitude is computed as:

\[
|\vec{v}| = \sqrt{u^2 + v^2}
\]

This transformation reduces dimensionality and simplifies initial correlation analysis. Instead of handling a vector-valued feature, a scalar representation is sufficient for preliminary assessment.

\section{Implementation}
\label{sec:visualization:implementation}

The implementation emphasizes modularity and computational efficiency. Data processing, application logic, and visualization are separated to ensure maintainability and reproducibility.

\paragraph{Technology stack:}
The application is built on \textit{Panel} and \textit{Bokeh}. Panel provides the application framework, manages layout, and coordinates reactive components, while Bokeh renders interactive visualizations in the browser. This combination integrates Python-based data processing and responsive web-based visualization into a single workflow.

\paragraph{Reactive update mechanism:}
When a user modifies parameters, an event-driven callback mechanism updates only the affected data sources. The update process follows four steps:
\begin{enumerate}
    \item Update internal data selection
    \item Trigger recalculation if necessary
    \item Update Bokeh data sources
    \item Refresh the visualization
\end{enumerate}


\paragraph{Performance considerations:}
Several design decisions ensure that the tool remains responsive even when handling large spatio-temporal datasets:
\begin{itemize}
    \item Conversion of ERA5 data to NetCDF to optimize I/O performance
    \item Precomputation of wind magnitude to reduce runtime complexity
    \item Modular handling of glacier metadata and time series
    \item Incremental updating of visual components to minimize latency
\end{itemize}

\subsection{Adjustments and Controls}

The adjustments and controls section acts as the central configuration unit. Users can select variables, define aggregation options, and apply temporal filters.

Interactive filtering is a fundamental mechanism in time-oriented data analysis. Aigner et al. describe filtering as a key technique to reduce visual clutter and focus on relevant intervals \parencite{aigner_time_oriented_data}. The implemented slider-based time restriction enables targeted inspection of specific periods.

All parameter changes influence only subsequent visualization components and do not alter the original dataset definition.

\paragraph{Temporal Filtering}
\begin{itemize}
    \item \textbf{Daily hour selection:} 
    Multi-selection of synoptic hours (e.g., 00, 08, 16 UTC) for intra-day filtering of ERA5 variables.
    
    \item \textbf{Yearly mode:} 
    Aggregation of time series to annual resolution.
\end{itemize}


\paragraph{Physical Range Filtering}
\begin{itemize}
    \item \textbf{Wind speed range (m/s):} 
    Continuous interval restriction of values.
    
    \item \textbf{Wind direction range (°):} 
    Circular angular interval selection within $[0,359]^\circ$.
\end{itemize}


\paragraph{Visual Parameters}
\begin{itemize}
    \item \textbf{Line transparency ($\alpha \in [0,1]$):} 
    Controls opacity of rendered time series.
\end{itemize}



\paragraph{Trendline Configuration}

To support the analysis of temporal developments, the application provides several methods for computing trend lines.
These methods are available for both weather variables and glacier-related data.

The numerical calculations are based on established scientific Python 
libraries, namely \textit{NumPy} and \textit{Pandas} 
\parencite{numpy_harris_2020, pandas_mckinney_2010}. 
In the following, the functional principles of the implemented methods are briefly described.

\vspace{1em}
\noindent\textbf{Pre-smoothing (optional)}

If enabled, the original time series $y(t)$ is smoothed using a centered moving average with window length $W$. For each time step, the mean of the values within the selected window is calculated:

\begin{equation}
\tilde{y}(t) = \frac{1}{N} \sum_{i=1}^{N} y(t_i)
\end{equation}

This optional step reduces short-term variability before applying the 
actual trend method.

\vspace{1em}
\noindent\textbf{Rolling Mean}

The rolling mean calculates a local average over a defined time window $W$. 
For each time step, the mean of the surrounding observations is computed:

\begin{equation}
\hat{y}(t) = \frac{1}{N} \sum_{i=1}^{N} y(t_i)
\end{equation}

This method provides a simple and intuitive smoothing of the time series.

\vspace{1em}
\noindent\textbf{Exponentially Weighted Moving Average (EWMA)}

The EWMA assigns higher weights to recent observations and lower weights 
to older values. It is defined recursively as

\begin{equation}
\hat{y}_t = \alpha y_t + (1-\alpha)\hat{y}_{t-1},
\end{equation}

where $\alpha$ controls the influence of recent data. 
This method reacts more strongly to recent changes than the rolling mean.

\vspace{1em}
\noindent\textbf{Polynomial Regression}

For polynomial regression, a polynomial of degree $d$ is fitted to the time 
axis:

\begin{equation}
\hat{y}(x) = \sum_{k=0}^{d} a_k x^k.
\end{equation}

The coefficients $a_k$ are determined using least squares minimization. This approach provides a smooth global approximation of the overall trend.

\vspace{1em}
\noindent\textbf{Annual Linear Trend}

In this approach, annual mean values are first computed. A linear model is then fitted to these aggregated values:

\begin{equation}
\hat{y}(Y) = mY + b,
\end{equation}

where $m$ represents the average annual rate of change. 
This method is particularly suitable for identifying long-term climatic trends.

\subsection{Execution Controls}

The interaction area also provides control elements for applying and updating

    \item \textbf{Set trend:} Applies the selected trend method to the current dataset.

\subsection{Map}

The map view enables spatial feature screening. Regional differences in wind magnitude or temperature indicate whether spatial heterogeneity should be considered in later modeling stages.

The combination of a spatial overview and a linked temporal detail view follows the overview+detail principle described in time-oriented visualization literature \parencite[p.380]{aigner_time_oriented_data}. The map provides global context, while the time series plot offers detailed inspection for selected locations.

Spatial inspection supports decisions such as:

\begin{itemize}
    \item Regional covering of the data
    \item Identification of spatial outliers
    \item Assessment of spatial data coverage
\end{itemize}
